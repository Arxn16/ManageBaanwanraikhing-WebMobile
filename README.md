# บ้านแว่นไร่ขิง — ระบบจัดการร้านแว่นตา (เวอร์ชัน server)

ระบบเก็บข้อมูลลูกค้า ค่าสายตา และยอดขายของร้าน เปิดใช้ผ่านเบราว์เซอร์ได้ทั้งมือถือ แท็บเล็ต และคอม
ที่ต่อ Wi-Fi วงเดียวกับเครื่อง server ไม่ต้องใช้อินเทอร์เน็ต

## ความสามารถ

- เพิ่ม แก้ไข และลบลูกค้า บันทึกการมาครั้งใหม่ และดูประวัติค่าสายตาทุกครั้ง (R/L: SPH, CYL, AX, VA, ADD, PD/SH)
- แดชบอร์ดยอดขายรายวัน สัปดาห์ เดือน ปี หรือช่วงวันที่ พร้อมยอดค้างชำระ
- ส่งออกข้อมูลเป็น Excel หรือ CSV
- กดการ์ด "ค้างชำระ" ในแดชบอร์ดเพื่อดูรายชื่อคนค้าง และกด "รับชำระ" (รับครบหรือบางส่วน) ได้ทันที
  ในหน้ารายละเอียดลูกค้าก็มีปุ่มรับชำระที่การมาแต่ละครั้ง
- พิมพ์ได้ 2 แบบจากหน้ารายละเอียดลูกค้า: 🖨️ ใบค่าสายตา (ไม่มีราคา)
  และ 🧾 ใบรวม (มีราคาและยอดชำระ) ทั้งสองแบบเลือกกระดาษการ์ด A6, A5/A4 หรือเครื่องพิมพ์ใบเสร็จ 80 มม. / 57–58 มม.
  แก้ชื่อร้าน ที่อยู่ เบอร์โทร LINE และข้อความท้ายใบได้ที่ `public/shop.json`
- 👓 แผง "ช่วยดู" ใต้ช่องค่าสายตา (หน้าเพิ่ม/บันทึกครั้งใหม่/แก้ไข และในรายละเอียดลูกค้าแต่ละครั้ง) สำหรับคนในร้านดูประกอบ
  **ไม่บันทึกลงฐานข้อมูล และไม่พิมพ์ลงใบ** เปลี่ยนตามทันทีที่พิมพ์ค่า
  - สรุปสายตาคร่าวๆ ตามเกณฑ์ (ใช้ค่ารวม SE = SPH + CYL/2): สั้นตาม IMI 2019 (≤ −0.50 สั้น, ≤ −6.00 สั้นมาก),
    ยาวตาม AOA (≤ +2.00 น้อย, +2.25 ถึง +5.00 ปานกลาง, > +5.00 มาก), เอียง 0.50–1.00 / 1.25–2.00 / > 2.00
    พร้อมแนวเอียง (ตามกฎ/ผิดกฎ/แนวเฉียง) และค่าที่วัดได้แบบที่ร้านเรียก (วัดสายตาได้ "สั้น 125 เอียง 50")
  - เตือนเมื่อสองตาต่างกันตั้งแต่ 2.00 · เทียบกับการมาครั้งก่อน (สั้น/ยาวเพิ่มหรือลดเท่าไหร่)
  - อายุ 40 ขึ้นไป ค่าบวกที่ไม่มี ADD จะบอกว่าถ้าเป็นค่าแว่นอ่านหนังสือ = ยาวตามอายุ
  - ค่าแปลง (กดเปิด): สลับรูปแบบ CYL บวก/ลบ, ค่ารวม SE, คอนแทคเลนส์ (คิดระยะห่างตา 12 มม. เมื่อเกิน ±4.00),
    แว่นอ่านหนังสือ (SPH + ADD), ระยะคอม (SPH + ADD/2 โดยประมาณ), VA 20/xx = 6/xx = ทศนิยม
  - เป็นการประเมินคร่าวๆ ช่วยดูเท่านั้น ไม่ใช่การวินิจฉัย ค่าคอนแทคเลนส์ต้องลองใส่จริงก่อนสั่ง
    ค่าที่อ่านไม่ได้ (เช่น `+-0.50` ไม่รู้ว่าบวกหรือลบ) จะขึ้นว่า "อ่านค่าไม่ได้" ให้เห็น
- วันที่ที่พิมพ์เป็นปี พ.ศ. (เช่น 2569-03-02) ระบบแปลงเป็น ค.ศ. ให้เอง ทั้งตอนบันทึก ตอนนำเข้า และข้อมูลเดิมตอนเปิดระบบ
- ต้องใส่ PIN ก่อนใช้งาน เครื่องที่ใส่แล้วจะจำไว้ 30 วัน
- สำรองข้อมูลอัตโนมัติวันละครั้ง และมีปุ่มดาวน์โหลดไฟล์สำรองในหน้าเมนู
- นำเข้าข้อมูลจากไฟล์ `.db` `.sql` หรือ `.json` ด้วยคำสั่งเดียว (ใช้ย้ายข้อมูลจากโปรแกรมเดิม หรือกู้คืนจากไฟล์สำรอง)

## เริ่มใช้งานครั้งแรก (Docker)

1. ติดตั้ง [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Mac/Windows) หรือ Docker Engine (Linux)
2. **ย้ายข้อมูลเดิม** ทำได้หลังเปิดระบบแล้ว ดูหัวข้อ [นำเข้าข้อมูล](#นำเข้าข้อมูล) (ถ้ายังไม่มีข้อมูล ระบบจะสร้างฐานข้อมูลใหม่ให้เอง)
3. เปิดไฟล์ `.env` แล้วเปลี่ยน `APP_PIN` เป็นรหัสของร้าน (ถ้าไม่มีไฟล์นี้ ให้ก๊อปจาก `.env.example`)
4. เปิด Terminal ในโฟลเดอร์นี้ แล้วรัน

   ```bash
   docker compose up -d --build
   ```

5. ทดสอบในเครื่องนี้ที่ <http://localhost:3000>

> Mac/Windows: เปิดตั้งค่า Docker Desktop ให้ "Start Docker Desktop when you sign in"
> ระบบจะเปิดเองทุกครั้งที่เปิดเครื่อง

## เปิดใช้จากมือถือ

1. ให้มือถือต่อ Wi-Fi วงเดียวกับเครื่อง server
2. หา IP ของเครื่อง server
   - Mac: รัน `ipconfig getifaddr en0` (หรือดูที่ System Settings → Wi-Fi → Details)
   - Windows: รัน `ipconfig` แล้วดูบรรทัด IPv4 Address
   - Linux: รัน `hostname -I`
3. เปิดเบราว์เซอร์ในมือถือไปที่ `http://<IP>:3000` เช่น `http://192.168.1.10:3000` แล้วใส่ PIN
4. เพิ่มไอคอนไว้ที่หน้าจอ
   - iPhone (Safari): ปุ่มแชร์ → "เพิ่มไปยังหน้าจอโฮม"
   - Android (Chrome): เมนู ⋮ → "เพิ่มลงในหน้าจอหลัก"
5. **ล็อก IP ของเครื่อง server ในเราเตอร์** (DHCP reservation) ไม่อย่างนั้นถ้า IP เปลี่ยน มือถือจะเข้าไม่ได้

ถ้ามือถือเข้าไม่ได้ ให้ตรวจว่า

- เครื่อง server เปิดอยู่ และ `docker compose ps` แสดงสถานะ `healthy`
- Firewall ของเครื่อง server อนุญาต Docker / พอร์ต 3000
- Wi-Fi ที่ใช้ไม่ใช่ Wi-Fi สำหรับแขก (มักตั้งไว้ไม่ให้เครื่องในวงเห็นกัน)

## ใช้มือถือ Android เป็น server (Termux)

ใช้มือถือ Android เครื่องหนึ่งเป็นเครื่อง server แทนคอมได้ เครื่องอื่นในร้านเปิดผ่าน Wi-Fi เหมือนเดิม

**ติดตั้งครั้งแรก**

1. ลงแอป [Termux](https://f-droid.org/packages/com.termux/) จาก F-Droid หรือ GitHub (ไม่ใช่ Play Store)
   ถ้าอยากให้ระบบเปิดเองตอนเปิดเครื่อง ลง [Termux:Boot](https://f-droid.org/packages/com.termux.boot/) จากที่เดียวกัน แล้วเปิดแอป Termux:Boot 1 ครั้ง
2. เปิด Termux แล้วพิมพ์ `termux-setup-storage` (กดอนุญาต) ตามด้วย `pkg install -y unzip`
3. เอาไฟล์ `banwaen-termux.zip` ไปไว้ในโฟลเดอร์ Download ของมือถือ (หรือส่งผ่าน SSH ดูหัวข้อถัดไป)
4. พิมพ์

   ```bash
   cd ~ && unzip -o ~/storage/downloads/banwaen-termux.zip
   sh ~/Manage-Banwaenraikhing/termux/install.sh
   ```

   สคริปต์จะลงโปรแกรมที่ต้องใช้ นำเข้าข้อมูลลูกค้า ตั้งให้ระบบทำงานเบื้องหลัง (ดับแล้วเปิดใหม่เอง)
   และบอกที่อยู่สำหรับเปิดจากเครื่องอื่น รันซ้ำได้ ข้อมูลที่มีในมือถืออยู่แล้วจะไม่ถูกทับ
5. ตั้งค่ามือถือ
   - แบตเตอรี่ของแอป Termux ตั้งเป็น "ไม่จำกัด" (Unrestricted) และเสียบสายชาร์จไว้
   - อย่ากด Exit ที่แจ้งเตือนของ Termux (ระบบจะปิดไปด้วย)
   - ล็อก IP มือถือในเราเตอร์ และในตั้งค่า Wi-Fi ของมือถือให้ใช้ MAC ของเครื่อง (ไม่ใช่ MAC แบบสุ่ม)
   - มือถือบางยี่ห้อ (Xiaomi, OPPO, vivo, Huawei) ต้องเปิด "เริ่มอัตโนมัติ" (Autostart) ให้ Termux และ Termux:Boot ด้วย

ใช้ git แทน zip ก็ได้: `pkg install -y git && git clone https://github.com/Arxn16/ManageBaanwanraikhing-WebMobile.git ~/Manage-Banwaenraikhing`
แล้ววางไฟล์ `.db` ไว้ในโฟลเดอร์ Download (ตั้งชื่อขึ้นต้นด้วย `banwaenraikhing`) ก่อนรัน `install.sh`

**พิมพ์คำสั่งจาก Mac แทนพิมพ์ในมือถือ (SSH)**

ในมือถือพิมพ์ครั้งแรก: `pkg install -y openssh` แล้ว `passwd` (ตั้งรหัสผ่าน) แล้ว `sshd` แล้ว `whoami` (ได้ชื่อผู้ใช้ เช่น `u0_a234`)
จากนั้นบน Mac

```bash
scp -P 8022 banwaen-termux.zip u0_a234@<IP มือถือ>:~/   # ส่งไฟล์เข้ามือถือ
ssh -p 8022 u0_a234@<IP มือถือ>                         # เข้าไปสั่งงานมือถือ
```

ถ้าส่งไฟล์ด้วย `scp` ให้ใช้ `unzip -o ~/banwaen-termux.zip` แทนในขั้นที่ 4 ถ้าปิด Termux ไปแล้วต้องพิมพ์ `sshd` ในมือถือใหม่

**คำสั่งที่ใช้บ่อยบนมือถือ**

| งาน | คำสั่ง |
| --- | --- |
| ดูสถานะ | `sv status banwaenraikhing` |
| รีสตาร์ต | `sv restart banwaenraikhing` |
| ปิดชั่วคราว / เปิด | `sv down banwaenraikhing` / `sv up banwaenraikhing` |
| ไม่ให้เปิดเองอัตโนมัติ | `sv-disable banwaenraikhing` (เปิดกลับ: `sv-enable banwaenraikhing`) |
| ดู log | `tail -f $PREFIX/var/log/sv/banwaenraikhing/current` |
| นำเข้าข้อมูล / กู้คืน | `cd ~/Manage-Banwaenraikhing && node server/import.js ~/storage/downloads/<ชื่อไฟล์>.db` |
| อัปเดตโค้ด | unzip ไฟล์ใหม่ทับ แล้วรัน `sh ~/Manage-Banwaenraikhing/termux/install.sh` อีกครั้ง |

ถ้าพิมพ์ `sv` แล้วขึ้น `unable to change to service directory` (มักเกิดหลังติดตั้งครั้งแรก) ให้ปิดหน้าต่าง Termux หรือ ssh แล้วเปิดใหม่ 1 ครั้ง

**ข้อควรระวัง**

- ใช้ server ที่เดียว เมื่อย้ายมาใช้มือถือแล้วให้ปิด server บน Mac (`docker compose down`) ไม่อย่างนั้นข้อมูลจะแยกเป็นสองชุด
- ไฟล์สำรองอัตโนมัติถูกก๊อปไว้ที่โฟลเดอร์ `Documents/banwaenraikhing-backups` ของมือถือด้วย (นอกแอป Termux)
  ถ้าแอป Termux ถูกลบ ไฟล์ชุดนี้ยังอยู่ แต่ถ้ามือถือหายหรือเสีย จะหายไปด้วย
  จึงควรก๊อปโฟลเดอร์นี้ไปเก็บที่อื่นเป็นประจำ (คอม, Google Drive) หรือดาวน์โหลด "ไฟล์ .db" ในหน้าเมนูไปเก็บ
  (แอปอื่นที่ได้สิทธิ์อ่านไฟล์ในมือถืออ่านโฟลเดอร์นี้ได้ อย่าให้สิทธิ์แอปที่ไม่น่าไว้ใจ)
- ถ้า Termux ถูกลบ: ลง Termux ใหม่แล้วติดตั้งตามขั้นตอนเดิม สคริปต์จะเจอไฟล์สำรองล่าสุดใน Documents แล้วถามว่าจะนำเข้าไหม ให้กด Enter
- ถ้าระบบดับเองและขึ้น `[Process completed (signal 9)]` (Android 12 ขึ้นไปปิดโปรเซสเบื้องหลัง)
  - Android 14 ขึ้นไป: ตั้งค่า → ตัวเลือกสำหรับนักพัฒนา → เปิด "Disable child process restrictions"
  - Android 12L–13: ต่อสายกับคอมแล้วรัน `adb shell "settings put global settings_enable_monitor_phantom_procs false"`

## นำเข้าข้อมูล

ใช้ตอนย้ายข้อมูลจากโปรแกรมเดิม หรือกู้คืนจากไฟล์สำรอง รองรับไฟล์ 3 แบบ

- `.db` ไฟล์ฐานข้อมูลของโปรแกรมเดิม (บน Windows อยู่ที่ `C:\Users\<ชื่อผู้ใช้>\AppData\Roaming\banwaenraikhing.db`) หรือไฟล์สำรองใน `data/backups/`
- `.sql` ไฟล์ dump ของ SQLite
- `.json` ไฟล์ที่มี `"customers": [...]` หรือไฟล์ JSON ที่ดาวน์โหลดจากหน้าเมนู

**ขั้นตอน**

1. สร้างโฟลเดอร์ `data/import/` แล้ววางไฟล์ที่จะนำเข้าไว้ในนั้น
   (ห้ามวางทับ `data/banwaenraikhing.db` ตรงๆ)
2. เปิด Terminal ในโฟลเดอร์โปรเจกต์ แล้วรัน (เปลี่ยนชื่อไฟล์ให้ตรง)

   ```bash
   docker compose exec app node server/import.js data/import/banwaenraikhing.db
   ```

3. ระบบจะสรุปจำนวนรายการ ยอดขาย และสิ่งที่ต้องระวังให้ดู ถ้าถูกต้อง พิมพ์ `y` แล้วกด Enter
4. รีเฟรชหน้าเว็บ ข้อมูลใหม่จะขึ้นทันที ไม่ต้องรีสตาร์ต

- การนำเข้า **แทนที่ข้อมูลทั้งหมด** ในระบบด้วยข้อมูลจากไฟล์ ก่อนนำเข้า ระบบจะสำรองข้อมูลเดิมไว้ที่
  `data/backups/before-import_<วันเวลา>.db` ให้อัตโนมัติ ถ้าผิดพลาด ใช้คำสั่งเดียวกันนำไฟล์นั้นกลับเข้ามาได้
- เติม `--dry-run` ท้ายคำสั่งถ้าอยากตรวจไฟล์อย่างเดียวโดยยังไม่นำเข้า
- ถ้าไม่ได้ใช้ Docker ให้รัน `npm run import -- data/import/<ชื่อไฟล์>`

## สำรองและกู้คืนข้อมูล

- **อัตโนมัติ** ระบบเก็บไฟล์สำรองไว้ที่ `data/backups/` วันละ 1 ไฟล์ เก็บย้อนหลัง 30 ไฟล์ (ปรับได้ที่ `BACKUP_KEEP` ใน `.env`)
- **ด้วยมือ** ที่หน้าเมนูมีปุ่ม "ไฟล์ .db" (ใช้กู้คืน) และ "ไฟล์ JSON" (เปิดอ่านได้)
- ควรก๊อปโฟลเดอร์ `data/backups/` ไปเก็บไว้ที่อื่นเป็นระยะ เช่น USB หรือ Google Drive เผื่อเครื่องเสีย
- อย่าก๊อปไฟล์ `data/banwaenraikhing.db` ขณะระบบทำงาน ให้ใช้ปุ่มดาวน์โหลด หรือปิดระบบก่อน

**วิธีกู้คืน** ใช้คำสั่งนำเข้ากับไฟล์สำรองที่ต้องการได้เลย ไม่ต้องปิดระบบ

```bash
docker compose exec app node server/import.js data/backups/<ชื่อไฟล์สำรอง>.db
```

## รันแบบไม่ใช้ Docker

ต้องมี Node.js 22.13 ขึ้นไป (แนะนำ 24)

```bash
npm install
npm start
```

ระบบอ่านค่าจากไฟล์ `.env` และเก็บข้อมูลไว้ที่โฟลเดอร์ `data/` เหมือนกัน

## โครงสร้างโฟลเดอร์

| ที่อยู่ | คืออะไร |
| --- | --- |
| `server/` | ตัว server: API, ฐานข้อมูล, PIN, สำรองข้อมูล |
| `public/` | หน้าเว็บ (HTML, JavaScript, CSS, ไอคอน) · `public/js/rx-tools.js` = ตัวคำนวณแผง "ช่วยดู" |
| `styles/input.css` | ต้นฉบับ CSS (Tailwind) |
| `test/` | ชุดทดสอบ API และตัวคำนวณค่าสายตา (`npm test`) |
| `termux/` | สคริปต์ติดตั้งและรันบนมือถือ Android (Termux) |
| `data/` | ฐานข้อมูลและไฟล์สำรอง **ไม่ขึ้น git** |
| `legacy-electron/` | เวอร์ชัน Electron เดิม เก็บไว้เผื่อต้องใช้ **ไม่ขึ้น git** |

## สำหรับนักพัฒนา

```bash

npm run build:css  # สร้าง public/css/app.css ครั้งเดียว (Docker ทำให้เองตอน build)
npm test           # ทดสอบ API
```

- ฐานข้อมูลเป็น SQLite (`node:sqlite` ที่มากับ Node.js) ตาราง `customers` เหมือนเวอร์ชันเดิมทุกคอลัมน์
  การมาครั้งถัดไปของลูกค้าเก็บเป็นแถวใหม่ที่มี `parent_id` ชี้ไปที่ลูกค้าหลัก
- API หลัก: `/api/customers`, `/api/customers/:id/visits`, `/api/visits/:id`, `/api/dashboard`,
  `/api/sales?from=&to=`, `/api/export/{csv,xls}`, `/api/backup/{download,json,status}`

## ความปลอดภัยของข้อมูลลูกค้า

- ชื่อ เบอร์โทร ที่อยู่ และค่าสายตาเป็นข้อมูลส่วนบุคคล (PDPA) ห้าม commit `data/` หรือไฟล์ `.db` ขึ้น git
  (`.gitignore` กันไว้ให้แล้ว)
- ใช้ PIN อย่างน้อย 6 หลัก และอย่าเปิดพอร์ตนี้ออกอินเทอร์เน็ต (ไม่ต้องตั้ง port forwarding ที่เราเตอร์)
- ใส่ PIN ผิด 10 ครั้ง ระบบจะล็อก 10 นาที ถ้าเปลี่ยน PIN ทุกเครื่องต้องใส่ PIN ใหม่

## สิ่งที่แก้จากเวอร์ชัน Electron เดิม

- วันที่คำนวณตามเวลาไทย เวอร์ชันเดิมใช้เวลา UTC ทำให้ช่วงก่อน 7 โมงเช้าวันที่เพี้ยน ยอด "เดือนนี้/ปีนี้"
  ไปนับวันสุดท้ายของเดือนก่อนด้วย และตัวกรองรายเดือนไม่นับวันสุดท้ายของเดือน
- แก้ข้อมูลการมาครั้งหนึ่งแล้ว ช่องรายละเอียดไม่ถูกล้าง และไม่ไปบันทึกทับครั้งอื่น
- ลบลูกค้าแล้ว ประวัติการมาทุกครั้งถูกลบด้วย (เดิมค้างอยู่และยังนับในยอดขาย)
- ตัวกรองยอดขายในแดชบอร์ดแสดงผลได้แล้ว และตารางลูกค้าล่าสุดแสดงคอลัมน์ตรงกับหัวตาราง
- บันทึกลง SQLite ทีละรายการแบบปลอดภัย ไฟดับกลางคันข้อมูลไม่พังทั้งไฟล์ (เดิมเขียนทับทั้งไฟล์ทุกครั้งที่บันทึก)
